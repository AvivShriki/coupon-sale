# Coupon Sale

Marketplace בעברית למכירת מוצרים, שירותים וזכויות שכבר נרכשו ולא ינוצלו — כרטיסים
להופעות, חופשות, שוברים, טיפולי ספא, מנויים דיגיטליים ועוד.

הפלטפורמה **מחברת בין מוכר לקונה בלבד**. אין סליקה, אין ארנק ואין עמלה: התשלום
והעברת הפריט מתבצעים ישירות בין הצדדים, מחוץ למערכת.

כתובת הגרסה החיה: https://coupon.avivdigi.com

## הפעלה מקומית

```bash
npm install
npm run dev
```

| פקודה | מה היא עושה |
| --- | --- |
| `npm run dev` | שרת פיתוח |
| `npm run build` | בניית האתר הסטטי לתיקיית out |
| `npm run lint` | ESLint |
| `npx tsc --noEmit` | בדיקת טיפוסים |

| `node scripts/seed-categories-sql.mjs` | ייצור ה-INSERT של הקטגוריות ל-Postgres |

## סטאק

Next.js 15 עם App Router, TypeScript, Tailwind CSS v4, shadcn/ui ו-Zod.
האתר נבנה כאתר סטטי ומתפרסם ב-GitHub Pages. ה-backend המיועד הוא Supabase.

## ארכיטקטורה

**כל הנתונים נקראים בצד הלקוח.** בגרסה הזו אין שרת: האתר מתפרסם כקבצים סטטיים,
והמידע נקרא ונכתב בדפדפן. זו גם הארכיטקטורה שאליה מתחבר Supabase בהמשך — שם
הדפדפן פונה ישירות למסד הנתונים וההרשאות נאכפות ברמת השורה.

```
src/lib/data/types.ts    ← מודל הנתונים
src/lib/data/store.ts    ← מנוע הסינון, המיון והעימוד
src/lib/data/local/      ← מקור הנתונים הנוכחי: seed + שכבת שינויים ב-localStorage
src/lib/data/hooks.ts    ← הממשק שהרכיבים משתמשים בו
```

כשיחובר Supabase מחליפים את המימוש בתוך `hooks.ts`. אף מסך לא משתנה.

הקריאה מתבצעת בשני שלבים: הרינדור הראשון מחושב מנתוני ה-seed בלבד — בדיוק כמו
ה-HTML שנוצר בזמן הבנייה — ומיד אחריו נטענים השינויים המקומיים. כך אין אי-התאמה
ב-hydration והתוכן מוצג מיד, בלי מסך טעינה.

נקודות נוספות:

- **קטגוריות דינמיות** — `src/data/seed/categories.json` הוא מקור האמת היחיד
  (11 ראשיות, 70 תתי-קטגוריות). אותו קובץ מייצר גם את ה-SQL ל-Postgres.
- **שדות לפי קטגוריה** — `src/lib/categories/category-fields.ts` מגדיר אילו שדות
  נוספים מוצגים לכל קטגוריה. אשף הפרסום ועמוד המודעה מרנדרים אותם אוטומטית,
  והערכים נשמרים בשדה `attributes` מסוג JSONB.
- **תאריכי הנתונים** — נגזרים מקבוע ולא מהשעון החי, אחרת ה-HTML מהבנייה לא היה
  תואם לרינדור בדפדפן. בפריסה האוטומטית מוזרק תאריך הבנייה, כך שהתוכן נשאר טרי.
- **RTL** — האתר כולו `dir="rtl"`, גופן Heebo, ומרווחים בלוגיקה של `ms-*`/`me-*`.
- **תמונות** — עטיפות SVG מקומיות, בלי תלות בשירות חיצוני.

## מה עובד

עמוד בית, עמודי קטגוריה ותת-קטגוריה, חיפוש עם סינון ומיון שנשמרים בכתובת,
עמוד מודעה מלא, אשף פרסום בן 6 שלבים, אזור אישי עם עריכה והשהיה, מועדפים,
דיווח על מודעה, ופאנל ניהול.

בגרסת התצוגה הנוכחית ההתחברות והנתונים שנוצרים נשמרים בדפדפן של המבקר בלבד:
כל מבקר רואה את נתוני הדמה ואת מה שהוא עצמו יצר. התחברות עם כתובת שמתחילה
ב-`admin@` פותחת את פאנל הניהול.

מודעה שנוצרת בדפדפן מקבלת מזהה שאין לו עמוד סטטי. דף ה-404 מזהה כתובת של מודעה
ומציג אותה מהנתונים המקומיים, כך שגם רענון של הכתובת עובד.

## פריסה

האתר נבנה ומתפרסם אוטומטית ב-GitHub Actions בכל דחיפה ל-master:
`.github/workflows/deploy.yml`.

דרישות חד-פעמיות:

1. ב-GitHub, בהגדרות הריפו תחת Pages, לבחור מקור: GitHub Actions.
   ב-GitHub Pages לריפו פרטי נדרש מנוי בתשלום, ולכן הריפו צריך להיות ציבורי.
2. ב-Cloudflare, להוסיף רשומת CNAME: `coupon` → `avivshriki.github.io`,
   עם Proxied, בדיוק כמו `lottery` ו-`family`.
3. קובץ `public/CNAME` כבר מכיל את `coupon.avivdigi.com` ונכנס לבנייה.

## מה עדיין דורש Supabase

1. יצירת פרויקט והרצת `supabase/migrations/0001_init.sql` ואחריו `0002_seed_categories.sql`.
2. החלפת המימוש ב-`src/lib/data/hooks.ts` בקריאות ל-Supabase.
3. החלפת מנגנון ההתחברות ב-`src/lib/auth/auth-context.tsx` ב-Supabase Auth.
4. העברת המועדפים מהדפדפן לטבלת `favorites`.
5. העלאת תמונות ל-Storage במקום שמירתן בתוך המודעה.
6. הרצה מתוזמנת של `expire_listings()` לסגירת מודעות שפג תוקפן.

שימו לב: מרגע שיש מסד נתונים אמיתי, חלק מהעמודים יצטרכו רינדור בשרת, והאתר יעבור
מאחסון סטטי לפלטפורמה שמריצה Next.js.

מבנה ה-DB, האינדקסים ומדיניות ה-RLS כבר כתובים במיגרציה: משתמש עורך ומוחק רק את
המודעות שלו, קטגוריות וניהול מודעות פתוחים למנהל בלבד, ומועדפים פרטיים למשתמש.

## אבטחה

- ולידציית Zod על כל יצירת מודעה, גם בצד הלקוח וגם בסכמה שתיאכף בשרת.
- אין מפתחות בקוד; כשיתווסף Supabase ייחשף רק `NEXT_PUBLIC_SUPABASE_ANON_KEY`.
- בעמוד מודעה לא מוצגים קודי מימוש או ברקודים, ויש אזהרה מפורשת על כך בפרסום.
- רשימת פריטים אסורים להעברה מוצגת באשף הפרסום ודורשת אישור מפורש.
- מנגנון דיווח על מודעה ומנגנון תפוגה למודעות.
