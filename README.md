# Coupon Sale

Marketplace בעברית למכירת מוצרים, שירותים וזכויות שכבר נרכשו ולא ינוצלו — כרטיסים
להופעות, חופשות, שוברים, טיפולי ספא, מנויים דיגיטליים ועוד.

הפלטפורמה **מחברת בין מוכר לקונה בלבד**. אין סליקה, אין ארנק ואין עמלה: התשלום
והעברת הפריט מתבצעים ישירות בין הצדדים, מחוץ למערכת.

## הפעלה

```bash
npm install
npm run dev
```

האתר עולה ב-http://localhost:3000 (בסביבה המקומית כאן הוגדר פורט 3200).

סקריפטים נוספים:

| פקודה | מה היא עושה |
| --- | --- |
| `npm run build` | בניית גרסת פרודקשן |
| `npm run lint` | ESLint |
| `npx tsc --noEmit` | בדיקת טיפוסים |
| `node scripts/generate-covers.mjs` | יצירת עטיפות SVG לקטגוריות |
| `node scripts/seed-categories-sql.mjs` | ייצור ה-INSERT של הקטגוריות ל-Postgres |

## סטאק

Next.js 15 (App Router) · TypeScript · Tailwind CSS v4 · shadcn/ui · Zod.
ה-backend המיועד הוא Supabase (Postgres + Auth + Storage), והפריסה ל-Vercel.

## ארכיטקטורה — שכבת נתונים מוחלפת

ההחלטה המרכזית בפרויקט: **אף רכיב ממשק לא ניגש לנתונים ישירות**. הכול עובר דרך
ממשק אחד:

```
src/lib/data/types.ts   ← המודל + הממשק DataSource
src/lib/data/index.ts   ← db — נקודת הכניסה היחידה
src/lib/data/mock/      ← מימוש מעל seed מקומי (פעיל כרגע)
```

כשמחברים Supabase מוסיפים `src/lib/data/supabase/` עם אותו ממשק ומחליפים את
המימוש ב-`index.ts` לפי `DATA_SOURCE`. אף מסך לא משתנה.

נקודות נוספות:

- **קטגוריות דינמיות** — `src/data/seed/categories.json` הוא מקור האמת היחיד
  (11 ראשיות, 70 תתי-קטגוריות). אותו קובץ מייצר גם את ה-SQL ל-Postgres.
- **שדות לפי קטגוריה** — `src/lib/categories/category-fields.ts` מגדיר אילו שדות
  נוספים מוצגים לכל קטגוריה (אמן ומקום להופעות, יעד ותאריכים לחופשות וכו').
  אשף הפרסום ועמוד המודעה מרנדרים אותם אוטומטית; הערכים נשמרים ב-`attributes` (JSONB).
- **RTL** — האתר כולו `dir="rtl"`, גופן Heebo, ומרווחים בלוגיקה של `ms-*`/`me-*`.
  מחירים ומספרים עטופים ב-`.num` כדי שייקראו נכון בתוך טקסט עברי.
- **תמונות דמה** — עטיפות SVG מקומיות ב-`public/covers/`, בלי תלות בשירות חיצוני.

## מה עדיין דורש Supabase

1. יצירת פרויקט והרצת `supabase/migrations/0001_init.sql` ואחריו `0002_seed_categories.sql`.
2. כתיבת `src/lib/data/supabase/` — אותו ממשק `DataSource` מעל `@supabase/supabase-js`.
3. החלפת מנגנון ההתחברות ב-`src/lib/auth/auth-context.tsx` ב-Supabase Auth.
4. העברת המועדפים מ-localStorage לטבלת `favorites`.
5. העלאת תמונות ל-Storage (bucket `listing-images`) במקום data URL.
6. הרצה מתוזמנת של `expire_listings()` לסגירת מודעות שפג תוקפן.

מבנה ה-DB, האינדקסים ומדיניות ה-RLS כבר כתובים במיגרציה: משתמש עורך ומוחק רק את
המודעות שלו, קטגוריות וניהול מודעות פתוחים למנהל בלבד, ומועדפים פרטיים למשתמש.

## אבטחה

- ולידציה כפולה: בצד הלקוח לחוויית משתמש, ובצד השרת (Zod) לפני כל כתיבה.
- אין מפתחות בצד לקוח מלבד `NEXT_PUBLIC_SUPABASE_*`; `service_role` לעולם לא נחשף.
- בעמוד מודעה לא מוצגים קודי מימוש או ברקודים, ויש אזהרה מפורשת על כך בפרסום.
- רשימת פריטים אסורים להעברה מוצגת באשף הפרסום ודורשת אישור מפורש.
- מנגנון דיווח על מודעה, ומנגנון תפוגה למודעות.
