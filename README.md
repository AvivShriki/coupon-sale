# Coupon Sale

Marketplace בעברית למכירת מוצרים, שירותים וזכויות שכבר נרכשו ולא ינוצלו — כרטיסים
להופעות, חופשות, שוברים, טיפולי ספא, מנויים דיגיטליים ועוד.

הפלטפורמה **מחברת בין מוכר לקונה בלבד**. אין סליקה, אין ארנק ואין עמלה: התשלום
והעברת הפריט מתבצעים ישירות בין הצדדים, מחוץ למערכת.

כתובת הגרסה החיה: https://coupon.avivdigi.com

## הפעלה מקומית

```bash
npm install
npm run dev
```

| פקודה | מה היא עושה |
| --- | --- |
| `npm run dev` | שרת פיתוח |
| `npm run build` | בניית האתר הסטטי לתיקיית out |
| `npm run lint` | ESLint |
| `npx tsc --noEmit` | בדיקת טיפוסים |
| `node scripts/generate-covers.mjs` | יצירת עטיפות SVG לקטגוריות |
| `node scripts/seed-categories-sql.mjs` | ייצור ה-INSERT של הקטגוריות ל-Postgres |

## סטאק

Next.js 15 עם App Router, TypeScript, Tailwind CSS v4, shadcn/ui ו-Zod.
האתר נבנה כאתר סטטי ומתפרסם ב-GitHub Pages. ה-backend המיועד הוא Supabase.

## ארכיטקטורה

האתר מתפרסם כקבצים סטטיים, והדפדפן פונה ישירות ל-Supabase. אין שרת ביניים,
וההרשאות נאכפות במסד הנתונים עצמו ברמת השורה. המפתח הציבורי מוטמע בקוד בכוונה —
הוא לא מעניק שום הרשאה בפני עצמו.

```
src/lib/data/types.ts     ← מודל הנתונים
src/lib/data/remote/      ← הגישה ל-Supabase: מודעות, מועדפים, אחסון תמונות
src/lib/data/hooks.ts     ← הממשק שהרכיבים משתמשים בו
src/lib/supabase/client.ts ← יצירת החיבור
```

**קטגוריות:** במסד הנתונים לכל קטגוריה יש מזהה uuid, ובממשק עובדים עם המסלול
שמופיע גם בכתובת. התרגום בין השניים מרוכז ב-`remote/categories.ts` בלבד.

**אישור מודעות:** האישור הוא דגל נפרד מהסטטוס. הסטטוס שייך למוכר (פעילה,
מושהית, נמכרה) והאישור שייך למנהל, כך שהשהיה והחזרה לא דורשות בדיקה מחדש.

נקודות נוספות:

- **קטגוריות דינמיות** — `src/data/seed/categories.json` הוא מקור האמת היחיד
  (11 ראשיות, 70 תתי-קטגוריות). אותו קובץ מייצר גם את ה-SQL ל-Postgres.
- **שדות לפי קטגוריה** — `src/lib/categories/category-fields.ts` מגדיר אילו שדות
  נוספים מוצגים לכל קטגוריה. אשף הפרסום ועמוד המודעה מרנדרים אותם אוטומטית,
  והערכים נשמרים בשדה `attributes` מסוג JSONB.
- **RTL** — האתר כולו `dir="rtl"`, גופן Heebo, ומרווחים בלוגיקה של `ms-*`/`me-*`.
- **תמונות** — מוקטנות בדפדפן לפני ההעלאה ונשמרות באחסון של Supabase. כל משתמש
  כותב רק לתיקייה שנושאת את המזהה שלו.

## מה עובד

עמוד בית, עמודי קטגוריה ותת-קטגוריה, חיפוש עם סינון ומיון שנשמרים בכתובת,
עמוד מודעה מלא, אשף פרסום בן 6 שלבים, אזור אישי עם עריכה והשהיה, מועדפים,
דיווח על מודעה, ופאנל ניהול עם תור אישורים.

מודעה חדשה ממתינה לאישור מנהל ואינה נראית לציבור עד שתאושר. המוכר רואה אותה
באזור האישי שלו בכל שלב.

הרשאת ניהול נקבעת בשדה התפקיד בטבלת המשתמשים, ולא ניתנת לשינוי מהאתר.

## אבטחה — מה נבדק בפועל

- משתמש מחובר שניסה לאשר לעצמו מודעה — הדגל נשאר כבוי.
- משתמש מחובר שניסה להפוך את עצמו למנהל — התפקיד נשאר ללא שינוי.
- גולש אנונימי אינו רואה מודעות שלא אושרו.

ההגנה נאכפת בטריגרים ולא רק במדיניות השורות, כי מדיניות השורות ב-Postgres
אינה יודעת להגביל אילו עמודות מותר לעדכן.

## פריסה

האתר נבנה ומתפרסם אוטומטית ב-GitHub Actions בכל דחיפה ל-master:
`.github/workflows/deploy.yml`.

דרישות חד-פעמיות:

1. ב-GitHub, בהגדרות הריפו תחת Pages, לבחור מקור: GitHub Actions.
   ב-GitHub Pages לריפו פרטי נדרש מנוי בתשלום, ולכן הריפו צריך להיות ציבורי.
2. ב-Cloudflare, להוסיף רשומת CNAME: `coupon` → `avivshriki.github.io`,
   עם Proxied, בדיוק כמו `lottery` ו-`family`.
3. קובץ `public/CNAME` כבר מכיל את `coupon.avivdigi.com` ונכנס לבנייה.

## מה נשאר לעתיד

- רינדור בשרת לעמודי המודעות, כדי שייכנסו למנועי חיפוש. דורש מעבר מאחסון סטטי
  לפלטפורמה שמריצה Next.js.
- הרצה מתוזמנת של `expire_listings()` לסגירת מודעות שפג תוקפן.
- תנאי שימוש ומדיניות פרטיות שעברו עורך דין.
